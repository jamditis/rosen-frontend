[HIGH] ISSUE #1: Featured work "People Formerly Known as the Audience"
  (feat-11) link does not match any CSV record URL.

  Featured URL: https://pressthink.org/2006/06/the-people-formerly-known-as-the-audience/

  CSV records for the same piece:
    RECORD-00191: http://archive.pressthink.org/2006/06/27/ppl_frmr_p.html  (PressThink)
    RECORD-00607: https://pressthink.org/2006/06/27/ppl_frmr.html          (PressThink)
    RECORD-00070: https://www.huffpost.com/entry/the-people-formerly-known_b_24113 (HuffPost)

  None match the featured URL exactly. The featured URL appears to be
  a WordPress pretty-permalink that may redirect to one of the above.

  Impact: Featured works open in a new tab (target="_blank"), so the
  link will still work if pressthink.org redirects properly. However,
  there is no way for the archive to highlight this record when users
  click it, since the URL-to-record lookup would fail.

  Recommendation: Update the featured URL to match RECORD-00191 or
  add RECORD-00191's URL as a ?record= deep link instead.

[LOW] ISSUE #2: Featured works link externally, not to archive records.
  The FeaturedSection.js component opens all links in a new tab. Users
  leave the archive when clicking featured works. Consider linking to
  the archive record modal instead (e.g., ?record=RECORD-00191).

[LOW] NOTE: The 5 non-CSV featured entries (dissertation reader,
  PressThink blog, Yale Books link, berks.psu.edu PDF, church of the
  savvy) are external URLs that correctly do not need CSV records.

  Title: "Asymmetry between the major parties fries the circuits of
         the mainstream press"
  CSV date: 2015-11-29
  URL path: pressthink.org/2016/09/... (implies September 2016)
  Summary: References "the 2016 US presidential election campaign"

  The article was published in September 2016, not November 2015.
  The URL clearly contains /2016/09/. The date 2015-11-29 is almost

  getEra() logic, 2016 maps to "View from Nowhere (10s)" which is
  correct for a 2016 article -- but 2015 also maps there, so the era
  is coincidentally correct. The year display is still wrong.

  Minor discrepancy -- the URL says November but the CSV says October.

  These records have author values that appear to be malformed Python

    (Should be: "Jay Rosen, Amanda Michel" or "Jay Rosen; Amanda Michel")

  and commas. RECORD-00060 is a FEATURED_WORK (feat-15, The Guardian).
  RECORD-00092 is a key "View from Nowhere" record in The Atlantic.

4. PUBLISHER FIELD FORMATTING
========================================================================

[MEDIUM] ISSUE #6: 5 records have raw quoted-list publisher values.
  The export script does pub = rawPub.trim() without cleaning quotes.

  RECORD-00010: pub = "PressThink", "Comment is Free"
  RECORD-00011: pub = "Tomdispatch.com", "Salon.com"
  RECORD-00012: pub = "Romenesko", "Huffington Post"
  RECORD-00013: pub = "TomDispatch.com", "Mother Jones", "Alternet", "Lew Rockwell"
  RECORD-00014: pub = "PressThink", "Huffington Post", "Romenesko", "Brad DeLong's blog"

  These display as raw strings with embedded quote marks in the
  archive UI. The first publication should be used as the primary,
  or the cleanTags() function should be applied to the publisher field.

[MEDIUM] ISSUE #7: 16 PressThink-URL records have non-PressThink publishers.
  Records with pressthink.org URLs but publisher listed as the
  syndication target (e.g., HuffPost, Salon, TomDispatch) rather
  than PressThink. This is arguably correct if the piece was
  originally syndicated, but is confusing when the URL points to
  pressthink.org. Examples:

  RECORD-00011: URL=archive.pressthink.org, pub="Tomdispatch.com", "Salon.com"
  RECORD-00289: URL=archive.pressthink.org, pub=TomPaine.com
  RECORD-00441: URL=archive.pressthink.org, pub=Columbia Journalism Review

8. EXPORT FILTERING LOGIC REVIEW (export-archive-data.js)
========================================================================

Reviewed the full export pipeline. Key observations:

CORRECT BEHAVIORS:
  - Records with verified=false are filtered out (line 548)
  - Records with title < 5 chars or "Untitled" are filtered out (line 549)
  - Records with no date AND url='#' are filtered out (line 550)
  - CLIP- records are force-verified (line 98) -- all 83 are also
    verified in CSV, so this is redundant but not harmful
  - Social records are force-verified (line 97) -- correct
  - Thread member posts are removed from social records to avoid
    duplication with THREAD container records
  - Reposts/RTs are filtered out
  - Short replies with generic titles are filtered out
  - Dissertation record is manually added (hardcoded, line 539)

POTENTIAL EDGE CASES:

  a) Publisher field not cleaned (line 85: pub = rawPub.trim())
     Multi-value publisher strings with embedded quotes display
     verbatim. See Issue #6 above.

  b) Author field not cleaned (line 79: author = .trim())
     Python list syntax in author fields displays verbatim.
     See Issue #5 above.

  c) The getEra() function uses hard-coded decade boundaries:
       < 2000 -> "Public Journalism (90s)"
       < 2010 -> "Web & Blogging (00s)"
       < 2020 -> "View from Nowhere (10s)"
       >= 2020 -> "Democracy in Crisis (20s)"

     The CSV itself has 12 different era values (some overlapping)
     which are ignored by the export. This is by design -- the export
     computes eras from dates. However, articles before 1990 (like
     the 1989 CLIP records) still get placed in "Public Journalism
     (90s)" which is slightly inaccurate.

  d) Category delimiter inconsistency: CSV uses both commas and
     semicolons as category delimiters. The cleanTags() function
     handles both (splits on [;,]), so this is correctly handled.

  e) 17 unverified records (all with empty URLs) will be filtered
     out. These include some notable titles:
       - "The People Formerly Known as the Audience" (RECORD-00683)
       - "Audience Atomization Overcome" (RECORD-00699)
       - "He Said, She Said Journalism" (RECORD-00700)
     These are duplicate entries without URLs that already have
     verified counterparts with URLs, so filtering them is correct.
